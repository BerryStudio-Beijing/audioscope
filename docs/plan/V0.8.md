# AudioScope by BerryStudio 0.8-alpha — 实现与测试记录

> 版本：`0.8.0-alpha.1` · 日期：2026-11-07
> 主题：把 0.7 的只读 Web UI 接上**本地实时桥**。
> 分支：`v0.8`；前一版：`v0.7.0-alpha.1`。

---

## 1. 本版目标

0.7 的 `ui` 是「生成一次快照 → 浏览器读死文件」。0.8 的第一步是补上传输层，
同时保持三条硬约束：

- 零第三方依赖（不允许 WebSocket 库、不允许 Python 运行时依赖）；
- 只监听 loopback，不联网、不暴露到局域网；
- 静态快照与实时快照共用同一个 JSON builder，避免字段漂移。

本版**只做实时桥**，WASAPI、真实 DUT 闭环、多页 PDF 仍留给后续 alpha。

## 2. 实现

| 文件 | 作用 |
|---|---|
| `src/app/ui_snapshot.cpp/hpp` | 唯一的快照 builder：meta/scope/spectrum/XY/channels/repair/reports/calibration |
| `src/app/live_server.cpp/hpp` | HTTP/1.1 静态文件 + WebSocket 101 握手 + 500 ms 推送 + `--smoke` 客户端 |
| `src/app/alpha_app.cpp` | `ui` 增加 `--live` / `--port` / `--interval` / `--capture` / `--device` / `--duration` / `--smoke` |
| `web/js/app.js` | `AUDIOSCOPE_LIVE` 模式下连接 `ws://<host>/ws`，合并快照并原地重绘；断线指数退避重连 |
| `web/styles/app.css` | `LIVE / 连接中 / 离线` 状态 pill |
| `Makefile` / `CMakeLists.txt` | 新源文件；Windows 链接 `ws2_32` |

### 2.1 传输层

- 监听 `127.0.0.1`，默认端口 8124，`--port 0` 由系统选空闲端口。
- 单线程 `select()` 事件循环：accept、HTTP 请求、WebSocket 握手、定时广播。
- WebSocket 握手只用自带 SHA-1 + Base64（RFC 6455 示例 key 可复现）；
  帧只发文本帧，长度 ≤ 64 KB 用 16 位、更大用 64 位长度。
- 静态文件仅从 `--out` 目录读，拒绝 `..` / 反斜杠 / 非 `/` 开头路径。
- `SO_SNDTIMEO` 1 s + `SIGPIPE` 忽略，慢客户端/已关闭客户端不会卡住广播。
- Windows 用 Winsock2；`socklen_t` 在 MSVC 下用 `int`。

### 2.2 数据源

- 默认 `live · synthetic`：1 kHz ± 80 Hz 缓慢摆动、−6 dBFS，每次推送推进相位，
  波形和读数可见地变化。
- `--capture` 才 `as_audio_open(--device, -2, 48000, 256)`；失败打印
  `as_audio_last_error()` 并回退合成源，仍标注真实来源。
- 每 tick 用 4096 点 Hann FFT + `as_tone_analyze()`，频率/THD 与静态路径一致。

### 2.3 UI

- 顶部 `LIVE` pill；断线显示 `离线`，重连中显示 `连接中`。
- 只更新当前页的读数、详情、页脚和 Canvas，不重建整个应用；`保持` 会冻结
  画面，符合 0.7 已有的交互语义。
- 服务端仍先注入一份静态 `AUDIOSCOPE_DATA`，首帧到达前页面不是空白。

## 3. 测试

环境：macOS 26（Apple Silicon），Apple clang 21；本机无 CMake / mingw-w64。

### 3.1 自动测试

```bash
cd alpha
make test
```

结果：

- `selftest`：**47/47 通过，0 failure**
- `scope` / `fft` / `ringtest` 通过
- 静态 `ui --out build/ui-test`：`index.html` 含 `AUDIOSCOPE_DATA`
- 新增 `ui --out build/ui-live-test --live --smoke`：
  `live bridge smoke: ok (loopback port <随机>，HTTP + WebSocket + snapshot)`

Smoke 覆盖：`GET /` 返回 200 + HTML；`/ws` 用 RFC 6455 示例 key 得到
`s3pPLMBiTxaQ9kYGzzhZRbK+xOo=`；首帧包含 `window.AUDIOSCOPE_DATA`、`meta:`、`scope:`。

### 3.2 手工验证

- 起 `ui --live --port 8772`，Python 标准库客户端连续收两帧：
  41 197 / 41 196 bytes，内容不同，首样本 `-0.47600 → 0.49984`。
- Chrome headless 1120×700 截图：
  - `#scope`：顶部 LIVE，页脚 `LIVE · SYNTHETIC`，波形随帧移动；
  - `#spectrum`：频谱与 THD 读数渲染正常，无空白。
- 断线重连：关闭服务后页面显示 `离线` 并按 0.5 s→8 s 退避重连。

### 3.3 CI

GitHub Actions `alpha`（run 42348284853，commit `9eb4a2c`）：

- macOS 15 / Apple Silicon：configure / build / ctest / package 全绿。
- windows-2022 / MSVC 2022：configure / build / ctest / package 全绿，
  包含新增的 `alpha_ui_live`（`ui --live --smoke`）。
- 期间修掉一个 MSVC 专有问题：`windows.h` 的 `min/max` 宏把
  `std::min(...)` 展开成非法 token（`error C2059/C2589`）；已用
  `NOMINMAX` + `(std::min)` 修正。

### 3.4 未验证

- **Windows 真机运行**：CI 只证明能编译/跑 CTest，没有在真实 Windows
  音频设备上打开浏览器验证 `ui --live`。
- **`--capture`**：本机终端无麦克风授权，打开输入会阻塞在系统授权；
  代码路径已实现，但没有在授权环境做端到端采集验证。

## 4. 安全与隐私

- 只 bind `127.0.0.1`，无外网监听、无遥测、无第三方依赖。
- 推送内容与 0.7 相同：不含用户名/绝对路径/校准文件内容；电压仍标注未校准。
- 软件不能保护声卡；实时桥不改变任何安全不变量。
